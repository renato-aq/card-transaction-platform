# 1. Record architecture decisions

**Status:** Accepted

## Context

Design choices in this project (messaging, persistence, consistency) have trade-offs that are not visible
from the code alone.

## Decision

Record significant decisions as Architecture Decision Records (ADRs) in `docs/adr`, using a lightweight
format: Context, Decision, Consequences.

## Consequences

- Reviewers can understand why the system is built the way it is.
- Superseded decisions stay in history and are marked as such instead of being deleted.
